# Native desktop presentation complexity and coverage

Rust/SDL2, no browser engine or JavaScript runtime. Gameplay and replays use a 1280 × 720 reference canvas, with responsive space for other aspect ratios; fixed authored menus and dialog sheets retain 1280 × 800 coordinates. The framebuffer uses the actual SDL drawable resolution, up to the existing 33,554,432-pixel cap. At the gameplay reference size the 8 px grid fits three tracks of 736, 248 and 296 logical pixels. The full 79 × 29 dungeon fits beneath the Chronicle on a separate 9 × 14 logical pixel tile scale.

## Work and storage bounds

P = framebuffer pixels, C = observed cells, A = actors, I = items, F = source-footprint entries, B = destination glyph pixels, G = atlas source pixels (128 × 232). A dirty input creates one detached observation. Core perception performs shared/direct/telepathic visibility and lighting; those costs are not claimed O(C). The desktop adapter then visits C cells, A actors, I items and F detached light-footprint entries, with bounded cardinal neighbors per cell and O(C + F + A + I) working storage. Entity filtering includes core visibility calls with their own costs. The immutable ability catalog is parsed once.

Cosmetic frames reuse the cached View and its Arc-backed, knowledge-filtered terrain snapshot; they do not call live observation, dispatch, RNG or mutable core state. Animated profile lighting/materials rebuild detached terrain colors in O(C + F + known-ray expansion) work, plus O(C) temporary colors/cells. Actor/item foreground and background colors follow this field using detached knowledge, material background and light. Fire adds a bounded per-cell palette interpolation and source material tone; no animation queries Run. Menu and persistent ambient effects schedule up to 12 frames/second; detached transient cues schedule up to 60 frames/second for their 240 ms lifetime. Reduced motion holds a static frame. Game paint is O(P + cell glyph pixels + UI glyph pixels); texture upload O(P). OS compositor costs depend on the platform. There is no per-cell live-world query during animation. Event polling sleeps eight milliseconds when idle.

Menu fire computes fixed 320 × 180 pixels with twelve authored flame tongues: O(320 × 180 × 12 + P) work and O(320 × 180) temporary image storage. Cosmetic seed/hash is independent from simulation RNG. Logo art is cloned during paint, adding its decoded image size in bandwidth and transient memory.

Cold ASCII atlas masks cost O(G) per glyph/size; warm tint/blit O(B). Cache holds at most 513 entries before reclamation on a miss. Non-ASCII/compound identities preserve all characters and rasterize font outlines each repaint, then fit a temporary mask; this is an explicit remaining optimization. UI glyphs use a character/size cache; fontdue internals are not assumed constant-time. Fonts/logo/atlas decode at startup. Bestiary retains only one decoded creature picture; switching entries decodes a PNG, O(decoded pixels) plus decompressor storage. All 81 authored PNGs remain compressed on disk. Manual text wrapping scales with entry text length and text glyph metrics. Chronicle materializes all archived messages on opening, O(message count + copied text bytes), then renders a viewport.

## Coverage and regression evidence

Default source terrain/material/light color functions are translated to Rust. 615 known terrain backgrounds and615 primary glyph/ink draws from frozen v48 renderDungeon match the actual Avatar fixture observation exactly. A preserved source-recorder tool and golden JSON support this scene regression. In addition,600 source-generated color cases compare exactly across ten materials, four knowledge states, five illuminations and three distances. This is not a whole-scene visual parity claim. Additional suites cover 41 custom light fields, 54 flicker samples, ten actor-ink fields and ten semantic hazard/fixture/fire scenes. These bounded suites do not establish all boundaries, combinations or raster animation parity. Historical boundary neighbors are conservative when a remembered neighbor conflicts with currently visible terrain. Whole-floor fit, hidden live terrain/actors suppression, deterministic hellfire, manual catalog/art presence and raster output have headless tests.

Full glyph strings, player/ally mode superscripts, heartless markers, minotaur arrows, remembered hazards/items and creature > fire > item > corpse ordering are implemented. Known fire, water, gas, wall sources and reflected light use detached cosmetic parameters. Exact flame/fixture tone and alpha parity, complete event producer coverage, blocked-beam path parity, spell link threads and complete HUD tooltips remain incomplete. Source route planning and interrupted click-to-walk are integrated; detached target previews are undergoing source fixture validation. Replay files now create a native generated initial run and support stepping, timed command playback and restart, with strict simulation revision checks. Existing source profiles load into a high-score/details viewer; the genuine-run archive path is implemented behind a disabled release gate, and invalid files are preserved. Migration fixtures never write ranked scores. The full appearance editor parses all 1,665 source controls, with exact preset/history semantics and explicit stored-only labels for consumers still being ported. Map materials, entities, fonts, path styling and visual light-field controls have native consumers; remaining UI typography/layout and feature consumers are tracked in appearance-native-coverage.md.

Menu uses authored two-column composition and labels. Gameplay uses top Chronicle, right health/energy/blessings/abilities and Pack toolbar. All 81 bestiary entries, 40 depth rosters, alternate forms, companions, original prose and artwork are reachable. Native generation/gameplay coverage is owned separately by core; artwork availability does not claim mechanical coverage.

Headless PNGs prove raster output only. Real-window screenshots and recordings must launch the SDL binary with a display and actual inputs. No full-game performance claim follows from these asymptotic bounds.

## Detached event cues

`DispatchOutcome.events` supplies observed-only positions and optional origins. The desktop attaches a cosmetic epoch; source cue timing uses 240 ms lifetime, 140 ms bolt travel, 56/86 ms lattice flashes and 18 ms full-intensity plateau. Every interpolated cell is independently culled against the detached current-knowledge mask, and fields merge by maximum strength. Actor glyphs are repainted above fields. Explosions persist for the displayed tick; free actions retain them, new tick/depth/load/restart/time-return clears them. The queue is capped at 256 cues. A bolt traverses at most the observed floor diagonal; overall cue preparation is O(C + L log C), where L is total generated cue tiles, with O(C + L) temporary storage. No beam geometry consults hidden world state; producer-side collision/event parity remains a core responsibility. Source link-thread overlays remain pending; known-cell route overlays use a detached coordinate set, with O(C + route length) paint preparation.

Native new-run form calls core startup::create_run with an explicit seed and authored Avatar/Blessed/Unblessed mode. Fresh seed selection alone uses six OS-randomu32 values via getrandom; core RNG is untouched by menus or animation. Generated, controlled-fixture and loaded-session provenance stays outside Run. Startup geometry/population complexity and parity are tracked by the core owners.

Bestiary uses the six deterministic source plate families, paper/ink/accent palettes and prose-first hierarchy. Whole-folio scrolling clips drawing to its detail viewport. Portable OFL Liberation serif/bold-sans replace unavailable proprietary Georgia/Impact faces; this is an explicit typography fallback, not a claim of identical outlines. Serif text currently rasterizes on each manual repaint, adding O(text glyph raster work); it is not a gameplay animation hot path.

Compact Chronicle groups only consecutive equal message/provenance pairs in the last30 events; colors match source text classification. The archive remains ungrouped. Wrapping and top-bar scrolling cost O(recent text bytes). Visible-creature cards are detached from knowledge-filtered actors, sorted by Chebyshev distance then ID in O(A log A), with O(A) storage; nearest threat uses the same source selection rule when no creature is selected. Sensed actors expose only the resource facts already exposed by frozen source observation. Player and observed-creature condition meters use the source duration/reference rules; full scene/rules inspection and pointer-transparent observed-creature hover use detached reports, including source-tested dynamic ability prose and combat forecasts.

Replay playback alone deliberately dispatches recorded commands on its120ms play timer; this is distinct from cosmetic animation. Replay errors stop playback without advancing the cursor. Replay files and profiles have32MiB read limits. Current fixture, replay and incomplete generated sessions do not archive ranked scores. Genuine native save/resume preserves future ranking eligibility outside Run; loaded sessions are not blanket-excluded.

## Read-only controls and modal projections

Ability rows have 144 frozen-source display cases (72 abilities, inactive and active). Hazard confirmations have 40 frozen-source cases and immutable-run assertions. Holding Rest deliberately dispatches Wait every 45 ms until the source knowledge comparison detects damage, threats, conditions, movement, a hazard, a choice, or non-advancing time. This explicit action timer is separate from cosmetic updates. Threat iteration retains source actor order. Blessing choices are blocking modal inputs and dispatch the core Choose command.

The main painter accepts detached observations only. Read-only adapters for abilities, hazards, Pack, statuses and inspection may query core state at input boundaries; each must apply the source knowledge rules before producing presentation data. See [Pack bounds and tests](pack-complexity.md) and [status projection bounds and tests](status-ui-complexity.md).

Native save envelopes preserve session provenance outside canonical Run/RNG. Loading is capped at 32 MiB. Atomic same-directory replacement writes and syncs the temporary file before rename. Automatic persistence runs before another input can read or replace the accepted state, after action timers, and before quit. New descents are persisted on their first completed frame. Non-development genuine death removes the resumable save, including on manual Save; fixtures use a separate default path. Invalid existing saves and provenance conflicts preserve original bytes and show an error. A failed quit save keeps the window open for export. Each accepted-command/new-state save reads and compares the existing S bytes, serializes the complete state, writes S bytes and syncs/atomically renames: O(S) byte work plus state serialization and filesystem latency, never O(1). A cached exact byte string, path and provenance avoid Engine loading/migration/history reconstruction for our own unchanged last-written bytes. Initial/external byte or path changes invalidate verification and invoke the full loader; malformed external changes are preserved. The cache retains O(S) bytes. Force-save and quit bypass the revision skip but retain exact-byte verification. Idle frames compare the revision/session/path key without filesystem I/O or serialization. Defaults are APPDATA/corpse-gods, macOS Application Support/corpse-gods, or XDG_CONFIG_HOME (otherwise ~/.config)/corpse-gods; ordinary native-save.json and controlled fixture-save.json are separate. The default profile.json and replays/ also live under this per-user directory, independent of launch/installation CWD; explicit --save, --profile and --replay-dir paths are retained. A persistent error banner is painted on every screen, so failed menu/window quits cannot hide the failure. Terminal summaries use the core cumulative score and heart projection; profile/replay writes remain behind a false release gate. Enabled-path tests verify genuine resume eligibility and fixture/replay exclusion. Profile preparation sorts existing archives according to the core stable ranking contract; file serialization/writes are O(encoded bytes). Invalid profiles are not overwritten. Calendar formatting uses UTC epoch milliseconds independently of simulation time.

## Mouse travel, inspection and appearance

Click-to-walk deliberately dispatches one Move every 45 ms. It stops on damage, changed observed threats, hazards, displacement, paralysis, meaningful input, or arrival. Route previews and hover reports refresh at dirty input boundaries, never on cosmetic frames. ## Solid-color Natural History revision (2026-10-20)

The native manual now caches one 81-entry roster sorted by first ordinary or conditional depth, then name and ID. Companion-only entries follow the depth-bearing roster. Startup sorting is O(N log N) time/O(N) storage; selection is bounded by N=81. Depth-based full-screen fills interpolate original parchment [239,232,204] through blood red [143,28,32] at depth25 to black at40. No environment scenery or animated background is rendered. Foreground creature material interactions remain bounded decoration within the illustration stage.

The primary regions are fixed: left navigation, two prose columns and center art/stat stage. Eight stats stay in the approved order. Inconsolata Regular400 and ExtraBold800 are genuine static instances of the bundled variable font at width100, not stretched glyphs or synthesized bold. All manual labels, headings, prose and stats use those fonts. Font metrics and rasterization share rounded per-glyph advances; selected-entry text fitting is O(C) at each of five candidate sizes16–20, with O(C) temporary layout memory. Draw cost includes O(G) glyph raster/mask work at native scale plus O(W*H) framebuffer fill and aspect-preserving picture work. Here C is selected authored character count, G is summed glyph raster pixels, and W/H are physical framebuffer dimensions. No claim of constant-time text rasterization is made.

Each entry has a Natural History section backed by an optional naturalHistory field. Until the owner supplies text, it uses the explicitly requested Latin placeholder. This is not invented canon. Future long histories must be checked against the no-scroll layout tests before release; there is no promise that arbitrary-length prose fits without an editorial/layout decision. No core simulation, RNG, creature mechanics or spawn data changed.

## Main-menu heartbeat and mode selection (October 30, 2026)

The main menu schedules cosmetic redraws at a 33 ms cadence (about 30 Hz), while
its pre-existing fire/ember phase retains the original 83 ms tempo. At startup,
the unchanged source emblem is partitioned into three registered, disjoint
original-pixel layers: veins, heart, and static foreground (including ribs,
skull and crown). Source images are not edited or regenerated. A modest anchored
heart-only scale follows a 1.08-second double beat. Delayed brightness fronts
travel outward along visible vein pixels; ribs are composited on top and never
transformed. The reduced-motion baseline reconstructs the exact original image.

Layer preparation is O(S) time/storage for S source pixels, once per painter.
Cached layers are shared via Arc; there are no per-frame image clones or loads.
Painting three layers is O(L) time for L destination logo pixels and O(1)
additional per-frame storage, with no simulation state/RNG access. Transparent
pixels are skipped. Actual throughput is hardware/resolution dependent, not
guaranteed by the scheduling interval. No hidden anatomical pixels are invented;
foreground occlusion preserves the original rib arrangement.

Eight fixed main-menu hit regions include the selected vessel/mode beside Descend.
Mouse or keyboard cycles the same three existing modes in O(1) time/storage.
The normal seed form displays the selected mode read-only; DEBUG floor setup
retains its independent setup selector. No save/replay format or simulation rule
changes. Keyboard traversal is bounded by the eight-item menu and skips disabled
Continue. Input and paint share the same hit-region constants.

## Gameplay HUD mockup composition

The 1280 × 720 reference uses a 952-wide map track and two 164-wide side rails. The header orders Chronicle, navigation, depth, and HP/NRG/status/blessings. The two-level footer places gods below the inspector and active rings below stats and shard count; Hearts/Potions span both levels. Full Pack is still available with I. The map fits its full 79 × 29 floor with 11 × 18 logical-pixel tiles at the default reference profile, flush with the playfield’s left edge; geometry adapts independently of simulation. Dialog sheets, methods of spending turns, engine commands and save formats are unchanged. The HUD resolves a fixed number of paint/hit/damage rectangles in O(1) time and space. Pack shortcuts add an O(I+B) projection on view refresh, for I inventory entries and B owned abilities used to resolve actual category capacities, with as many labels as usable items; click admission calls existing Pack blockers on demand. Known ground G and admitted creature C descriptors share an unlabelled scroll list with one fixed divider and one HP-only bar per directly observed, independent creature. The four visible status slots use constant-time color selection per slot and mark only the status strip when a temporary Burning pulse changes color; reduced motion uses a fixed tone. Footer ring names reuse the inventory scan and their wrapping follows the same bounded text measurement contract. Projection into cards and click identity remain O(G+C) apart from sorting and text layout. Ground jewelry projects only the base display name, while carried items retain full details; no save identities change. Text wrapping and visible raster retain the same bounds above. Retained and tile renderers invalidate the relocated regions and compare the detached quick-item/heart state, not hidden world data.
