# Revision 46 admission and persistence

Desktop new games and debug starts explicitly choose simulation revision 46. Loaded runs retain their recorded revision, and historical core convenience constructors retain their previous defaults. Revision 46 inherits revision 45 generation, fixed birth profiles, summoned-child profiles, Ruin pulses, revision 43 item actions, revision 44 Bleed Them behavior, and revision 45 Nova's 40-energy cost. Its separate gameplay change suppresses the active Shine owner's entire Shine light emission, including illumination of other actors and cells; admission does not retune actors or alter other mechanics. Revisions 45 and earlier retain their recorded rules.

The new exact header pairs are `corpse-r46-shine-suppression-v1` for command receipts and `corpse-r46-shine-suppression-metadata-v2` for ordered operations. All older IDs remain unchanged. Clean metadata recordings for revisions 41–46 resume and append without a checkpoint migration or mechanics upgrade. Header/revision mismatches, unknown IDs, future revisions and cross-grammar payloads fail before simulation execution. Framing, file limits, locks, synchronization, operation ordering and acknowledgments are unchanged.

## Complexity and validation

Each creation, load, replay, birth-overlay and resume admission boundary adds one member to a fixed whitelist: O(1) time and O(1) extra memory. Exact header selection/admission costs O(I), where I is identifier length, bounded by the existing 1,024-byte header cap. No new world, inventory or history traversal is introduced. Inherited profile lookup remains O(R), R = 91 fixed rows, per new actor after the one-time O(catalog bytes) parse. The existing roster cache is reused with its existing cache-miss construction cost; there is no new cache or per-turn allocation.

For an input of B bytes, certified resume still performs O(B + replay work) at load and O(B) exact verification once at attachment, with at most the existing 32 MiB recording retained until attachment or release. Replay work is the sum of the existing operations' transitive simulation costs, not a constant per command; the record limit does not impose a wall-clock CPU bound. Append attachment checks and all file/CRC/synchronization paths are unchanged. There are no new measured timing claims.

Focused tests in `crates/corpse-core/tests/revision46_admission.rs` and `crates/corpse-desktop/src/revision46_protocol_tests.rs` cover revision 45/46 generation equality apart from the revision field; all fixed ordinary and child birth profiles; a bounded 64-seed comparison for each of Witch and Queen summons including RNG; load/save preservation for 41–46; seed replay/restart; debug and legacy playtest entry points; future/fractional/nonfinite rejection without setup mutation or RNG calls; exact receipt/metadata header IDs, grammar and checkpoint-pair rejection; and clean 41–46 resume with ordered metadata append. Existing historical valid-revision tests remain; only unsupported-future fixtures move from 46 to 47. Desktop tests cover explicit revision 46 normal/debug starts and preserved selected seeds. The native gate is `tools/cargo.sh test --workspace`; gameplay and platform verification remain separate requirements. These test descriptions specify intended coverage, not a claim that the gate has run.
