# Embedded native artwork and executable resources

All 81 creature plates are compiled into the executable, selected by a sorted immutable ID index. No assets folder, environment variable, installation, or network is needed. Original PNG masters remain unchanged in `crates/corpse-desktop/assets/creatures`. Distribution-only WebP files preserve every source dimension and use quality 90/method 6. This is **lossy encoding**, not a claim of pixel-identical preservation. The current aggregate embedded art is 10,748,874 bytes. Requested master replacements have individual provenance and backups; unchanged masters are retained. `assets/art-distribution.json` records original and distribution hashes and dimensions. `tools/prepare-native-art.py` reproduces the encoding (Pillow/libwebp version can affect encoded bytes).

Visual inspection compared original and encoded images at1:1 detail crops of moonspawn, both Zillennia forms, Mini-Me, Hemogoblin, and Half-Here. Pixel shapes and fine lines remain recognizable; modest compression/color changes are present. No resampling, cropping, replacement, or AI regeneration is applied to creature art. Full source PNGs remain available to future builds.

The original `menu-logo.png` is unchanged. `window-icon.png` and the7-size ICO are platform-size nearest-neighbor representations of the whole logo, aspect-preserving with transparent padding. SDL receives the embedded PNG; Windows resource1/ICON embeds the ICO. Resource1/RT_MANIFEST embeds PerMonitorV2/PerMonitor DPI awareness. These resources are not evidence of Windows runtime testing.

## Complexity

Let N=81 plates, B=sum encoded bytes, P=selected plate pixels, L=max ID length. Build indexing costs O(N log N × L), generated source/index memory O(NL); compiler resource storage O(B). Lookup is O(log N × L) and O(1) extra memory. No plate is decoded at startup. A cold selection decodes one WebP in O(encoded selected bytes + P) work under the fixed-format decoder, with O(P) scratch/output memory and a32MiB decoder allocation limit; cached selected RGBA uses4P bytes (1254² plates use about6MiB; newer plates retain their individual source dimensions). Switching can transiently hold old and new decoded images; the full catalog is never decoded or retained. A warm selection has no decode or filesystem work; existing picture compositing remains proportional to drawn pixels. Embedded bytes occupy executable file-backed storage (resident paging controlled by OS), not an eagerly copied98MiB heap allocation.

Icon decoding occurs once for256² pixels: O(Picon) time/space, about256KiB RGBA plus decoder scratch. Icon/manifest resource compilation is constant-sized build work and adds no per-frame processing. Windows resource compilation uses WINDRES when supplied, otherwise the existing cross-SDK or windres on PATH. Linux runtime-only SDL installations retain the build-output linker alias fallback.

Regression: `tools/cargo.sh test -p corpse-desktop embedded_assets` decodes all81 distribution plates individually, verifies dimensions against original PNG masters and validates index coverage. Manual tests verify catalog references and scrolling. Package build omits loose plates; the Windows ZIP needs only its included SDL2.dll alongside the executable (no installer or extra art download).
