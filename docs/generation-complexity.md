# Native generation complexity

All work described here runs during floor creation or explicit diagnostic validation, never each live simulation tick. These are conservative implementation bounds, not measured language comparisons. V = tile count (2291,2500,3600 supported); R = room count; C = connector count; L<=24 = geological landmarks; S<=20 = setups; T=45 = authored setup definitions; A<=169 = stencil cells; F = authored fixtures; K<=32 = quality candidates. Current source geometry bounds are part of the contract, not adjustable performance fallbacks. Hash-table costs below assume expected constant membership; ordered tree membership adds log V where used.

- Room masks: local U<=360 cells. Coherent fill and two synchronous cellular passes O(U); monotone diagonal repair O(U²) worst case; largest-component stable sorting O(U+C_local log C_local). O(U) temporary storage.
- Passages: P emitted centerline/lateral cells. Current ordered-vector uniqueness is O(P²), O(P) storage. Corridor length is bounded by each calling algorithm.
- Vertical stairs: D<=40 floors,16 draws per candidate batch and four corner fallback candidates; O(D) time, constant bounded scratch. Domain plan: eight entries and bags<=6/3, fixed work.
- Correlated fields: O(V+Q) time/memory, Q lattice sites. f32 casts at lattice/output boundaries reproduce source storage; interpolation remains f64.
- Accretion: conservative O(V² log V), O(V+R+C) scratch including candidate sectors, local occupancy, graph and routes; at most180 attempts per target slot. The stage callback converts native integer graph metadata to shared schema using a transient serde value; this adds O(V+metadata) work/storage at each of two callbacks.
- Loop candidates: bounded13-step rays and bounded bend probes generate O(V) candidates; stable score sorting O(V log V), candidate path/BFS checks can total O(V²). Up to six accepted ordinary loops. Provisional acceptance callbacks are additional caller-supplied work; final topology allows48 checks, each with graph measurements below. Scratch O(V+R+C).
- Geology planning/materialization: conservative O(LV+V²+V log V) with ordered set maintenance, overlap scans, stable scores and component routes; O(V+L+R+C) scratch plus explicit provenance cell arrays. The V² allowance includes source-order-preserving removal from IndexSet core reservations. No geometry cache persists into simulation.
- Protected stairs: four proposals per stair, all four random draws consumed before rejection; each proposal may relabel O(V) connected cells. Fixed two stairs imply O(V+F), O(V+F) scratch.
- Connectivity: stable Dijkstra uses a binary heap and tie key(cost,index), O(V log V) per search; up to V productive terrain-consuming searches, O(V² log V), O(V+F) scratch. Diagonal repair adds at most V cells and can scan V per addition: O(V²).
- Cleanup fixed point: at most V+1 outer passes, each invoking connectivity/diagonal repair plus component and terrain scans. Conservative composition O(V³ log V), O(V+F) additional storage. Monotone carving bounds total productive searches more tightly in practice; no unproved amortized improvement is relied on. Currents/substrates/coastal refresh and protected authored lanes add O(V+S*A+F).
- Vents: candidate scoring and stable random-priority sort O(V log V), per-candidate fixture tests and gas checks O(V*F) conservative; basic sources B<=5. Reconciliation O(V+B*V+B²) after gas labeling, O(V+F) scratch.
- Lighting: room affiliation scans O(V*R). Candidate placement can invoke whole-floor access tests; conservative O(V*R+Qlight*V²), bounded source quota Qlight<=38, O(V+R+F) scratch. No simulation RNG consumption.
- Fire/gas safety: two eight-neighbor component labelings O(V), O(V) scratch; radius2 hearth and radius6 apron work is bounded per source. Candidate furnace checks reject components exceeding bounded apron capacity before scanning their cells. Repeated source/component exclusions can total O(F*V). Door removals preserve insertion order and can add O(F²).
- Authored setup compilation: T stencils of A<=169 cells, O(T*A) geometry/storage, plus catalog budget/rating helpers. Packing scans V anchors and A cells per template, up to S placements. Suffix repacking is at most O(S²*T*V*A); additionally up to O(S²*T) horde-feasibility checks, whose bounded-depth/budget dynamic-programming cost is documented by population. O(V+T*A+S) scratch with a fixed number of clearance masks (radii6/8). Ordered iteration and stable sorts affect deterministic choices. Stamp-to-world copying is O(S*A+F).
- Godbeast room: 81-cell disturbance score per grid candidate plus optional dry tap scan, O(V+R), O(V+R) candidate storage. Selected event metadata remains in Floor, no planning caches.
- Topology: iterative Tarjan O(V+E), E<=4V; planar obstacle regions with up to six bank-route probes per region conservatively O(V²). Measurement O((R+C+1)*V+V²), O(V+R+C) scratch. Finalization widens at most96 cells and adds at most two loops;48 loop acceptance checks each clone Floor and run O(V²) route alternatives. Clone cost O(V+metadata) is included, not treated as constant. The limit48 is fixed by source.
- Landmark survival: grouping O(LV), component labeling O(V) over the disjoint recorded regions, O(V+L) storage. The component membership set uses swap_remove only where iteration order is never observed; BFS/output order comes exclusively from original cells and cardinal neighbors.
- Generation diagnostics: stage hashes O(V) each, stage count<=10; metadata validation O(V+recorded graph/landmark cells+F), ignoring bounded field-name lengths. Shape parsing is separately owned by storage. Native integer-to-shared-schema conversions use transient serde values, O(metadata) work/storage; no JavaScript engine is involved.
- Blessing seed budget O(seed string length), constant draw; encounter quotas fixed three bands; retained loot allocation O(stored floors+stage records), at most two prior-floor lookups and bounded diagnostic keys. Horde and item execution belong to population, not this estimate.
- Full candidate search: at most K<=32 sequential candidates; total time is K times the above pipeline sum, retaining only one candidate at a time. Peak additional memory is O(V+graph metadata+L+T*A) plus shared immutable catalogs and transient serde conversion copies. All rejection gates remain fixed. No candidate fallback lowers quality.

Linux parity is established for tested cases; Windows execution and math-library behavior remain open. No speed claim follows from these bounds.
