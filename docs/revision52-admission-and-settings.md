# Revision 52 admission and action-animation settings

Revision 52 is the explicit opt-in for the designer's fixed Darkness area and approved outcome animations. Normal desktop starts and DEBUG starts now select 52. Prior saves and replays retain their own revision; the historical core helper remains 39. Revision52 inherits prior generation and early loot, then applies the documented natural-Fighter birth catalog and the explicitly revision-gated follow-up mechanics. The original admission receipt predates those additions; later profile-aware equality checks and the final gate must cover the resulting rules. It never silently falls back to an older numeric roster.

Exact admission lists include 52 but continue to reject skipped 47–49, fractional revisions and unknown future values. Desktop incremental journals and metadata have distinct 52 build IDs. They do not relabel 51 receipts. No saved simulation field is added for animation timing.

The basic Settings screen adds **Action Animations: Normal / Reduced / Instant**. It edits a draft until Apply. Back or Escape discards that draft. Display mode, resolution and animation preference are saved in one atomic settings transaction; a failed write leaves all prior stored values intact. The appearance studio's existing reduced-motion preference remains independent and takes precedence over Normal animation motion. Instant is the strongest action-animation setting. Old settings files default to Normal, invalid values fail transactionally without overwriting their source, and unrelated preset/display saves preserve the chosen animation mode.

## Complexity and bounds

Revision checks and mode selection are O(1) with no growing state. Opening Settings retains its existing O(min(M,256) log min(M,256)) display-mode sort for M monitor choices and O(min(M,256)) copied memory. The extra row has constant layout/raster work beyond text rendering. Applying preferences shares the existing O(J) settings serialization, validation, atomic write and sync for bounded JSON size J; the new enum adds constant bytes and no extra write. Simulation, RNG, replay commands and map visibility are not consulted by this UI preference. Native capture tests allocate O(W×H) RGBA pixels at three display sizes, at most one frame at a time. No timing claim is inferred from asymptotic bounds.
