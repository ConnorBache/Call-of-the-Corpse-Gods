# Fast mode main-menu control

Fast mode defaults off for this application session. The upper-left control explicitly displays ON or OFF. Click it, or traverse to it with Tab/Shift-Tab or Up/Down and press Enter/Space. It affects only new descents; Continue and replay loading retain their stored run flag. Toggling does not edit the seed, reroll gods, or mutate an existing run. Repeated activation flips the choice exactly once per input event, under the existing non-repeating input gate. A pending startup blocks changes and captures the mode when launched.

The fixed control is above the title and left of the anatomical illustration. The explanation reads “Floors 1, 3, ... 39, 40; hearts grant double blessings and stats. New descents only.” Existing button, seed and god geometry is unchanged. Fast descents follow floors 1, 3, 5, …, 39, then the final one-step descent to floor 40. Play from X’th floor retains the selected mode and supports every odd starting floor 1–39 plus 40. Other even floors are rejected clearly before seed generation or startup enqueueing, never converted to Normal mode. Arrow-key floor selection follows the reachable route, including 39↔40; typed values use the same validation. The DEBUG preparation screen states the active Fast route. Core reconstruction collects only prior floors on that route.

## Complexity

The input path has twelve fixed controls, O(1) time and extra memory per navigation, hover or activation. One boolean retains the next-descent choice. Mode validation is O(1) and floor text validation is O(T) for T input bytes before enqueueing the existing single background startup operation; seed preparation remains O(S) for at most 180 input bytes and run creation retains its core generation costs. No new save reads, simulation steps, RNG calls or persistent settings writes occur when toggling or painting.

Painting adds one 559×44 logical overlay and fixed text. At drawable scale s, raster work is O(559×44×s² + G), where G includes glyph rasterization/cache-miss work; the existing font cache and framebuffer/upload bounds apply. No timing claim is made. Tests cover shared mouse bounds, bidirectional traversal, art exclusion, visibly distinct states, pixel confinement, explicit startup flags, stored-run continuation, and rejection of unreachable debug starts, reachable debug construction, and route-aware arrow stepping. Finalized-route workspace/test compilation passed. These desktop UI tests have not yet been executed, and native screenshots and platform interaction remain unverified.

## Active-run and archive identity

Fast runs show “Fast mode” in the HUD (including active playback), terminal summary and profile detail/score rows. Summary records carry optional `fastMode: true`; missing/false flags retain legacy serialization and normal rendering. Score calculation, eligibility and sorting are unchanged. The replay browser labels files only after their existing explicit load has supplied metadata. Unopened filenames are not labeled: listing performs no new record reads, parsing or simulation. Loaded-path metadata is a bounded-by-library-size set, O(R) retained paths for R loaded fast records, with expected O(1) lookup per displayed row (plus path hashing); directory refresh clears it. Profile summaries add O(1) flag storage and label selection; existing record sorting and serialization bounds remain unchanged.
