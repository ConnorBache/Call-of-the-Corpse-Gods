# Negative illumination and chasm presentation

> Superseded in part by the 2026-11-09 clarification: chasms now use ordinary visible-terrain illumination, including negative-light foreground contrast rescue. The dark Brogue base palette and knowledge-safe remembered colors remain. Historical no-rescue claims and negative-light color receipts below do not describe the current implementation. See [ordinary chasm illumination](revision52-normal-chasm-illumination.md).

Only detached observation-to-pixel rendering changes. Simulation illumination, vision distance, sight/line-of-effect, probabilistic visibility, RNG, saves and replay rules are unchanged. Positive illumination keeps the existing calibration, including its zero-to-25 interpolation tangent.

For illumination -100, -75, -50, -25, 0, background multipliers are .05/.15/.30/.55/1, terrain glyphs .25/.40/.55/.75/1, and admitted creature glyphs .40/.55/.70/.85/1. Terrain saturation retention, including backgrounds beneath creatures, is .10/.25/.50/.75/1; creature retention is modestly greater. Saturation is reduced after source-color grading, so a tinted source cannot reintroduce strong color into darkness. Monotone cubic interpolation joins each table. At near-black exposure, retained background hue can quantize to neutral in 8-bit RGB. Background darkness continues below -100; foreground retains its -100 readability floor. Foreground-only contrast rescue targets 3:1 for ordinary terrain and 4.5:1 for creatures, smoothly fading into the unchanged zero-light path between -25 and zero. Contrast uses common-channel gain to retain the muted hue, falling back to whitening only when the hue cannot reach the target within gamut. It adds no lights, outlines, halos, visibility or range. Existing identity-specific outlines are unrelated and unchanged.

The knowledge filter remains authoritative: no new actors or live terrain are requested. Remembered terrain is dim neutral gray, independent of hidden live light/material changes. Default unexplored ground is black; explicit custom fog palettes remain authoritative. Dynamic foreground and background channels retain separate roles; cached illumination contains the scalar used to resolve roles, without consulting live simulation at paint time.

Brogue chasm uses static additive per-cell variation from the source tuple (7,7,15,4,4,8,0,false), percentages, against black. This chooses the original variable range (red/green 7–11%, blue 15–23%) rather than CE's optional true-color midpoint 9/9/19%. Three deterministic cosmetic hashes replace gameplay RNG; no clock-driven color dancing. Explicit custom chasm colors/backgrounds and global/fog/material grading remain authoritative, as does the frozen v48 adapter. Existing chasm boundary strokes use the same hue family rather than lavender. Current bare chasm glyphs are excluded from the generic negative-light contrast rescue, so darkness no longer brightens void ink above its neutral source color. The existing negative exposure and desaturation remain unchanged. Creatures, items, fire and other terrain keep their readability rescue, including over chasms. Default chasm boundary colors likewise bypass important-symbol whitening and blend the source blue-black ink against black on the chasm side, or against the existing adjacent terrain background on the other side. Existing stroke geometry, alpha and glyphs are unchanged. Edited color/background or grading controls retain the ordinary boundary pipeline. Source-range parity is asserted at neutral illumination; positive exposure remains calibrated normally. See [chasm contrast correction](r52-chasm-color-correction.md) for measured before/after colors and focused verification.

Complexity: O(C+A+U) per detached observation/rebuild, C output cells, A animation anchors and U underlays. Each color transform uses fixed five/nine-knot tables, fixed RGB arithmetic and a fixed 12-step contrast-gain search and existing constant-time fallback; O(1) scratch per cell. Cached scalar adds O(C) memory. Chasm uses three O(1) coordinate hashes per material/edge, four edges at most. Glyph raster and native pixel costs are unchanged. No new searches, world clones or visibility queries are added.
