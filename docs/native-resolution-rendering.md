# Native drawable-resolution presentation

> Historical fixed-layout baseline. Current responsive-window behavior is documented in [responsive-resolution.md](responsive-resolution.md). Gameplay now expands the logical canvas to the drawable aspect ratio, and allocation is bounded by a 33,554,432-pixel CPU budget plus driver and coordinate limits. The native rasterization and earlier verification history below are retained; their fixed-layout and OS-only-limit descriptions do not describe the current candidate.

The logical layout remains 1280×800 to preserve full-map fit, panel geometry and hit regions. The software framebuffer and SDL streaming texture now match the current drawable size W×H, including high-DPI displays. A uniform scale min(W/1280,H/800) and centered margins preserve aspect ratio. SDL no longer scales a fixed-resolution frame. Font outlines rasterize at device size; the existing high-resolution ASCII atlas produces masks at device-cell size. Compound and non-Brogue glyphs also rasterize outline masks at device-cell resolution; their per-instance temporary mask and resampling cost is O(mask area + destination cell area), plus fontdue outline work (uncached, as before). Original pictures are sampled directly into device pixels. Simulation, visibility, terrain observation and game glyph identity are unchanged.

Input arrives in SDL window points; mouse motion, buttons and wheel location are converted through the drawable/window ratio and inverse layout transform. Margins produce out-of-layout coordinates. Resize/fullscreen/DPI output changes recreate the buffer/texture, invalidate glyph caches and force repaint. Layout measurement remains in logical units to prevent wrapping/hit-target drift.

## Costs and limits

Let P=W×H, G be visible glyph instances, A the sum of their device bitmap areas, U unique rasterized glyph/size/face keys, B their total stored bitmap area, and S the ASCII source tile area (128×232). Each painted frame clears O(P), blends O(P+A) excluding pre-existing scene/animation work, uploads O(P) and presents O(P) through the SDL software renderer. Extra framebuffer and streaming texture memory are O(P); glyph/mask cache memory is O(B). The SDL copy is 1:1 at drawable resolution. Native library allocation/upload costs are included; SDL/platform-specific timing has not been benchmarked.

On resize, allocation/clear costs O(P); cache invalidation O(U+B) deallocation worst case. Font cache misses invoke fontdue outline rasterization, whose cost depends on contour complexity and output area (not claimed constant). ASCII area-filter cache misses cost O(S + device-cell area + boundary overlap) per unique mask; hot tinting costs O(device-cell area). Styled glyph cache is capped at 2048 entries, ASCII mask cache at approximately 513 before reset; ordinary glyph cache is cleared on resize and contains the text characters/sizes encountered at that drawable size. Picture sampling is O(destination device area), no intermediate upscaled framebuffer. Logical single-pixel effects expand to their device coverage, bounded by P over a full logical fill. Input mapping is O(1), no allocation.

Measured text ellipsis uses binary search over n Unicode scalar values, O(n log n) font metric work and O(n) temporary memory. Resource summaries suppress repeated reaction/fortune costs while inspection retains full detail. Headless --render-size WIDTHxHEIGHT accepts 1..8192 per axis; normal runtime dimensions follow SDL output (practical memory limit imposed by the OS). High resolution increases memory and fill costs quadratically with uniform scale.

## Verification

Tests exercise 2× font/ASCII mask raster size, resize cache invalidation, 1920×1080 aspect fit, high-DPI inverse mouse mapping, clipping and measured ellipsis. Use --render-test out.png --render-size 1920x1080 or --render-game out.png --render-size 2560x1440 with existing fixture arguments for visual QA. Run tools/cargo.sh test --workspace. Hardware-specific Retina/Windows DPI transitions still require platform verification; headless raster tests do not establish those platform behaviors.
