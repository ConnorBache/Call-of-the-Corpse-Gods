# Responsive native-resolution drawing

Gameplay uses the full drawable pixel buffer. A single uniform scale is the smaller of drawable width / 1280 and drawable height / 800. The logical canvas expands in the other direction, instead of stretching glyphs or leaving outer letterboxing. The right HUD follows the right edge; map/pack geometry uses the expanded frame, and command/footer content follows the bottom edge. Authored menus and fixed inspection/choice sheets stay centered at their original logical size. Pointer conversion selects the same coordinate space as the painted target, including queued screen changes and gameplay clicks outside a sheet.

Resizing prepares a new CPU buffer and SDL streaming texture before replacing either old resource. Zero or minimized drawables are skipped. Allocation, arithmetic, coordinate, and SDL texture-limit failure leaves the last valid renderer and game state intact and asks the player to resize smaller. The CPU framebuffer budget is 33,554,432 pixels (128 MiB RGBA), subject also to driver texture limits and coordinate bounds. This is resource-limited support, not unlimited allocation. A refused size may display the prior valid frame scaled by the window system; it is not reported as successful native-resolution rendering.

Full painting remains the default. The experimental tile path is conservatively disabled for non-16:10 committed canvases. Resize invalidates geometry-dependent caches; switching centered/responsive origin at unchanged pixel size does not rerasterize fonts. Fonts and map glyph masks continue to be rasterized at native scale rather than upscaling a fixed bitmap.

Warm full paint scales with actual output pixel coverage plus visible cell, text, and overlay work. Resize additionally allocates/initializes O(P) CPU pixels and a driver texture, discards old scale-dependent glyph caches, then paints the first new frame. These operations can temporarily retain both old and prepared framebuffers. Full texture upload is 4P bytes. The production resize event also requests the existing view refresh; isolated renderer timings must not be described as complete event/input latency.

## Automatic native pixels and manual selection

Settings now exposes `Auto (native pixels)` as the default resolution choice. A missing or null saved resolution remains automatic, including when the settings sheet is reopened or the display mode changes. In windowed mode, applying Auto keeps the current window extent; SDL's actual drawable dimensions supply the occupied physical pixels, including the operating system's DPI scaling. Do not multiply those dimensions by monitor density again. Automatic exclusive fullscreen selects the current monitor's desktop display mode rather than the 1280×800 layout baseline. Borderless uses the desktop mode as before.

Explicit existing resolution preferences remain compatible: windowed choices set SDL window dimensions, and fullscreen choices select a supported display mode. They do not introduce a second lower-resolution offscreen buffer; the renderer always draws at the resulting drawable resolution. Automatic resolution can be restored without deleting preferences. Opening settings retains a valid saved manual size even if it is absent from the newly attached monitor's advertised modes.

Deterministic tests cover automatic/manual selection and reopening, native buffers at 1×, 1.25×, 1.5× and 2× density, varying occupied window sizes through 4K, and equivalent pointer mapping for both gameplay and centered sheets. These do not establish hardware-specific monitor-switch or DPI event delivery; that remains platform verification.
