# Revision 50 creature names and selected glyph defaults

Current names are Pale Chomper / Greater Pale Chomper, Pale Gasser / Greater Pale Gasser, Corpse Fungus, and Devil's Samara Tree. Internal IDs (`pale:Biter`, `pale:Breather`, `bastidion`), ability IDs, gas field IDs and heart-species accounting keys are unchanged. Other creature glyphs/colors have not been redesigned beyond the explicit defaults below.

Selected defaults: Blorb `b` dark green `#28703c`; Bear `B` brown `#a47c55`; Dire Bear `B` literal black `#000000`; Corpse Fungus `F` (existing `#9fc875`); Hemogoblin Inventor `h` neon purple `#d600ff`; Yeti `Y` (existing `#D7E8F1`); Devil's Samara Tree brown `T` `#8a5a32`. Banshee `B` neon purple `#d600ff`; Long-legged Saidribee `b` brown `#8a5a32`; Short-legged Saidribee `b` and Saidribee Guardian `B` yellow `#f8d100`; Pale Birther `b` / Greater Pale Birther `B` keep `#b9b8b1` / `#f0e8dc`; Chimera `C` gold `#ddb435` while Cancer keeps red `#dc6969`; Sphinx `S` gold `#ffd34a` while Screamers keep their pale colors. Black is never silently substituted with gray. On directly visible default Dire Bears, a neutral `#bebebe` four-offset thin glyph outline provides contrast without filling or recoloring the floor. The same black identity is readable in the creature preview and bestiary. Telepathy, corpses, Dreamwalking and custom appearance keep their own existing treatments. The outline is cosmetic and contains no world lookup.

## Compatibility and coverage

Frozen v48 simulation catalogs remain unchanged. A revision-50 construction/load overlay changes only exact authored names and known old default glyph/colors; arbitrary actor names and non-default appearance survive. Explicit appearance-profile customizations remain authoritative, and exported/imported profile values are not silently migrated. The current built-in profile and manual advertise the new defaults. Older simulation revisions retain the previous actors, generation RNG and names; the current static bestiary/appearance labels describe current names.

Normal actor births, population fungi, machine corpses, summons, apparent identities, all loaded floors, nested pilots, carried hearts, inventory, ground, remembered/detected hearts, retained timeline states, pending haste and Future anchors use the existing revisioned construction/migration paths. New heart text uses the new names while rewards and counters remain canonical. Exact legacy aliases preserve inferred abilities, Greater Gasser hallucination gas, Chomper bite narration, Corpse Fungus no-revival/root behavior, adaptive-heart counters, status/hover flavor lookup and dynamic ability descriptions. Existing historical log lines are not rewritten; new events use current actors. No combat, stats, costs, balance or RNG changes are introduced.

## Complexity

Let A be actors across floors (including nested pilots), I held/ground/remembered/detected items, L their name bytes, S total detached state bytes, H retained timeline states (bounded by the existing history policy), and D nested Future anchors (existing admission limit 32). The overlay is O(A + I + L) time, O(L) transient string storage per name; actor/item COW detachment has the existing O(S) worst-case copy cost. Construction and the existing intrinsic-trait refresh add O(name bytes + nested pilot/item payload) fixed alias/default comparisons per actor, no new catalog scan or RNG draw. Unchanged names borrow storage; text is only allocated when an alias actually changes. R50 trait refresh reapplies the selected defaults after frozen legacy glyph normalization so older mappings cannot undo Inventor/Yeti/Fungus glyphs. Load normalization runs once for each state through the existing timeline/anchor orchestration, with the existing O(H*S) snapshot/serialization and anchor memoization costs, not per frame.

For C observed creatures, observation adds O(C) constant-size outline metadata/gating plus existing immutable-profile equality checks (bounded profile subtree sizes); strings and projection costs are unchanged. A black glyph uses four extra fixed offset draws plus the original center, O(G) native mask coverage per draw, O(1) extra retained metadata. Cold font/mask rasterization and GPU mask uploads retain existing cache-miss costs. Preview headers add the same fixed factor to the existing O(T²) worst-case measured wrapping and O(G) rasterization for T visible characters. No tile fill, additional visibility test, new cache, simulation query or persistent save field is added. Damage bounds retain the existing glyph spill margin; retained/tile/CPU/GPU pixel parity tests cover the outline at multiple native scales. These are asymptotic bounds, not measured timings.

### Approved tier superscripts
R50 uses 1/2/3 for lesser/ordinary/greater Ichor Fish, Sharks and Leviathans; Zillennia use 1–10 in existing quality order; Nightmares use 1–8 in existing tier order. Rank is shown above the glyph and is distinct from ally orders, which move below the glyph for ranked creatures. Two-digit rank 10 is right-aligned inside the tile. Rank is a stable tier indicator, not calculated live combat power. Normal visibility and deliberate hallucination/disguise presentation remain authoritative.

### Special birth palette consistency
Sphinx-room guardians keep their legacy birth profile, and nest residents and Queen summons keep their revision-33 birth profiles; each now receives the same R50 cosmetic overlay immediately on creation rather than first changing color on load. These bounded per-birth calls have the construction cost described above, introduce no RNG draws, and leave older revisions untouched. Caster-birth regressions compare the full old/new actor and RNG after explicitly applying only approved cosmetic changes to the expected actor; deep admission save/load equality covers generated Sphinx rooms and nests. Execution is recorded by the release owner.

### Appearance fixture provenance after palette edits
The frozen v48 appearance fixtures remain unchanged. `tools/rebase-r50-appearance-fixtures.py` derives v50 expected profiles with an explicit list of the 20 approved creature glyph/color changes; it does not query production output. Missing defaults are rebased, while explicit old imported profile fields remain byte-for-byte semantically unchanged. Store-action sequences and statuses are preserved, with assertions rejecting new creature-edit operations before rebasing. This keeps full edit/reset/undo/preset/import parity checks while allowing intentional built-in palette changes. The generator visits B JSON bytes and at most 20 fields per profile: O(B + 20P) time and O(B) memory for P profiles; it has no game runtime cost.

Saved appearance compatibility: the glyph validator additionally accepts the exact historical `(≬)` glyph only at `pale:Birther.glyph` and `pale:Greater Birther.glyph`. Other multi-character custom glyphs remain invalid. This preserves existing imported/saved full profiles without changing the new b/B defaults; the historical glyph remains an explicit override. A regression round-trips both overrides and rejects the glyph on another creature and a different non-ASCII glyph on Birthers. Validation adds only two fixed path comparisons, with constant time and space. The original full-profile edit/reset fixture inputs remain unchanged.
