# Engine admission and preview boundaries

Audit: 2026-10-19 21:46 UTC. This describes executable guards, not a claim of exhaustive parity. Final quiet workspace aggregate is still pending.

## Current runs

- Native generation, normal/haste dispatch, all 59 fixed authored creature-definition trait sets and dynamic Zillennia traits are admitted. Specialist source fixtures include active and selected hidden-floor compositions. Six actual generated Avatar seeds have 472 source-compared exploration commands; separate real desktop input traces are recorded by the acceptance owner.
- Player divine ownership uses `abilities::supported` plus the two temporal IDs. Active modes have an explicit engine allowlist. Unknown IDs and unknown condition keys fail transactionally.
- Ordinary arbitrary NPC divine ownership is deliberately narrower than player ownership. Mini-Me has a separate initial-starter whitelist: all fifteen authored starter IDs have passed 39 scenes/813 commands. This does not admit arbitrary modified `initialPlayer` divine sets.
- Remember has a separate copied-passive whitelist. All 44 authored enemy passive IDs now pass 139 source-compared scenes/1428 commands, including combat with and without Half Here. Unknown noncatalog copies remain rejected atomically.

## Remaining explicit boundaries

- `Dev` commands are parsed but rejected. Direct `Interact` and Mercuria lever bump interaction are executable; nine scenes/72 commands include adjacent activation, distant refusal and repeat interaction.
- Active-floor admission does not imply hidden-floor admission. `offscreen::validate_supported` rejects Half Here endpoints persisted on inactive floors, unknown creature traits, and divine modes outside its explicit upkeep subset. The exact Mini-Me starter whitelist is now admitted on inactive floors; 32 source-compared scenes/768 commands now cover clean/dirty profiles and lethal burning/venom disappearance. Ordinary NPC travel and queued ally arrivals have separate source fixtures.
- Invalid/missing active geometry, unrecognized condition names, unsupported item kinds/unknown equipment and unsupported equipment grants/crafts reject explicitly. These may be legacy/custom-state issues rather than failures on a newly generated Avatar.
- Raw internal damage/death helpers accept enumerated source damage causes. A new caller must supply the correct supported causal kind; arbitrary strings are not silently coerced.

## Save compatibility

Current typed schema acceptance and legacy migration are distinct. Exact current-state replay, temporal histories and selected old-save migration fixtures exist, but arbitrary old saves or manually edited saves are not promised. Migration ownership and current checkpoint are documented by the persistence worker. Inferred creature traits are capability-validated before action mutation; marked erased traits are never reinferred. Source raw-ability queries remain raw at their authored boundaries.

## Terrain and placement

Stairs, voluntary and forced falls, expiring finite flight, linked endpoints, corpse/item overflow and depth-40 discard use the authoritative travel/placement modules with source tests. Copied flight expiry can legally leave an actor grounded above a gap; admission no longer invents a fall in that source case. Full-floor placement no longer uses the old unused engine `ground_destination` helper on ordinary item/corpse death paths. Invalid coordinates/depths still reject.

## Verification limits

A capability entry is not exhaustive interaction proof. NPC divine combinations, arbitrary copied states, legacy undefined-vs-null history edges, all cross-floor combinations and presentation paths require their own evidence. No performance improvement or full-platform qualification follows from Rust compilation or these admission sets. Complexity and known logging/cache costs remain in `actors-combat-complexity.md`.
