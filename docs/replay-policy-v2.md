# Seed replay Revert-policy compatibility (isolated append trial)

Replay version1 has no Revert-policy field and always uses legacy selective Revert. Version2 explicitly specifies `revertPolicy`: `legacy` or `snapshot`. Only legacy may include `snapshotFrom`, the zero-based command offset before which legacy applies and from which snapshot overwrite applies. The boundary may equal command count; it is not a world tick. Unknown versions/policies, explicit null policy/boundary, and out-of-range boundaries reject before simulation. Restart reinstates the same plan.

The Run stores `replaySnapshotFrom` alongside its accepted command ledger: absent means known legacy, integer N means one legacy→snapshot switch,0 means snapshot from startup, and null means explicitly unknown historical policy. Snapshot/Future restore preserve this administration with the current replay ledger; historical snapshots and Future anchors omit it. New sessions have0. Import of known legacy saves switches at the existing command count. Old journal tails execute wholly under their recorded legacy policy before the switch is appended to provenance. Desktop recognition handles older unpublished snapshot-header recordings lacking this field as unknown, not a guessed boundary. Those saves remain playable/checkpointable, but checked seed export refuses them with an explanation. Previously exported ambiguous experimental version1 snapshot replays cannot be identified automatically; version1 retains its established legacy interpretation.

`ReplayRecord::try_from_run` is required for user exports. Compatibility `from_run` remains infallible for existing programmatic callers but emits an explicitly invalid unknown policy for unknown provenance; playback rejects it. No unknown ledger is silently certified.

## Complexity

Let C=accepted commands, S=current serialized world, H=retained snapshot bytes. New policy admission, transition, persistence field and per-command check are O(1) time/space. Export already clones C commands; policy adds O(1), so O(C+metadata bytes). Replay remains total simulation work over C commands; restart remains initial generation/import. Ordinary saves add only bounded integer metadata at checkpoint, with no new scan or checkpoint trigger. Snapshot cloning adds/clears one optional integer; restore preserves it O(1). Existing world validation/history export/import bounds are unchanged. Tests compare full current state plus exported retained history for fresh snapshot, version1 legacy and mixed-policy sequences, save/load, end-boundary and restart; unsupported metadata must fail before playback.
